# 實驗室團隊手冊（team-lab）

> 開工前讀這份 + 目標專案的 CLAUDE.md；收工後把**跨專案通用**的新教訓寫回這裡（專案專屬的寫進該專案 CLAUDE.md）。制度見 [[team-charter]]。

## 團隊班底與標準流程（team-lab）

**班底**（2026-07-15 定案；通用角色檔在 `~/.claude/agents/`，新增後**下一場對話**才生效）
- **主管（PM）**：team-lab skill 啟動的你。拆工單、調度、把方向級取捨升級給 Benson、dev 層自己拍板、統一 commit＋push、跟 Benson 回報。
- **lab-ux（UX 設計）**：有前端的專案，**dev 動手前先做一版可試用 demo 給 Benson 親自玩、確認方向**，再產設計規格給 dev。
- **lab-dev（開發）**：照確認的設計實作工具／App／自動化；開工前讀目標專案 `CLAUDE.md`。
- **lab-qa（品管）**：交付到 Benson 前實際驗收、會真的退件。
- **專案專屬角色**（如 office-cat 的 cat-dev／cat-qa／cat-writer）：只服務該特定專案（因其有特殊鐵律）；通用工作一律走上面 lab-* 角色。

**標準流程（有前端的專案）**：PM 拆需求 → **lab-ux 出可試用 demo → Benson 試用確認方向** → lab-dev 照定案實作＋實測 → lab-qa 驗收（過才放行、退件回 dev）→ PM 統一 commit＋push＋回報。
純後端／自動化／小改可跳過 UX：PM → lab-dev → lab-qa → PM。
> 精神：**設計先行、驗收把關**——把「做完才發現不對」擋在 demo 階段，把 bug 擋在 Benson 之前。（來源：recipe-book 之後 Benson 定調）

> **⭐ 派工鐵律（Benson 2026-07-15 明確要求，不可違反）**：所有工作**一律派給 team 的命名角色**（lab-ux／lab-dev／lab-qa 或專案專屬角色）走完整工作鏈；**不要再用通用執行者（`general-purpose`）兜著做**。若某任務現有角色都不適合，**主動建議 Benson 新增成員**、由他決定，不要自己拿通用執行者頂。（背景：食譜本整場開發都用通用執行者，Benson 要求之後不要再犯。）

## A. Benson 的做事偏好（派工與交付都要遵守）

- 結論要短、先講結果；他不看技術細節，深問再展開。
- 改完並確認完成後主動 commit + push（長期授權），不用等提醒。
- 改完**不要**自己背景重啟他的程式（taskkill 重開）——commit + push 後通知他自己重啟。
- 做完要能「看得到」：報告寫清楚成果在哪、怎麼用。

## B. Windows 環境雷（這台機器）

- Python 用 `py` 不是 `python`（python 會指到 Store 空殼）。
- PowerShell 5.1：沒有 `&&`／`||`；檔案編碼預設 UTF-16，寫檔記得 `-Encoding utf8`。
- **⚠️ 不要用 PowerShell 改既有的原始碼檔**（2026-08-11 踩到）：`Get-Content -Raw | ... | Set-Content` 這種 round-trip，PS 5.1 會把 UTF-8-without-BOM 當成 ANSI 讀進來，**中文註解整段變亂碼、LF 也被換掉**（該 repo 用 `.gitattributes` 強制 LF）。改檔一律用 Edit 工具；已經改壞就 `git checkout -- <file>` 救回來再用 Edit 重做。
- 路徑常含空格（`Claude Work`），指令一律加引號。

## D. 架構教訓（跨專案累積區）

- 角色分工要「writer 規格 → dev 實作 → qa 驗收（會真退件）→ PM commit」，驗收要真的擋，不是走過場。（來源：office-cat 首戰）
- 新建 agent 角色檔（`~/.claude/agents/`）要**下個 session** 才載入，當場叫不到。
- **Node spawn 本機 `claude` CLI（Windows）**：直接 `spawn('claude', …, {shell:true})` 會回 `cmd.exe ENOENT`。解法：先用 `where claude` 解析出真正的 `claude.exe`，`spawn(claudeExe, …, {shell:false})`、路徑用正斜線 → 繞開 cmd.exe，穩定。（來源：smm-cmm-library）
- **本機工具接 `claude` 當「AI 大腦」＝零額外 API 費用**：後端 `claude -p --output-format json` 拿 `.result`＋`.session_id`，多輪用 `--resume`，`--allowedTools`＋`--permission-mode acceptEdits` 限權讓它能改指定資料夾的檔。用的是 Benson 訂閱額度。**但**：Claude Desktop 內嵌版的訂閱授權是 host 即時注入、不落地到 Windows 認證管理員，所以另 spawn 的**標準全域 CLI 讀不到、會回「Not logged in」**。解法：Benson 在一般 PowerShell/CMD 跑一次 `claude` 完成登入（存進認證管理員），之後每次都讀得到。這是「接本機 claude 當大腦」類工具的通用前置條件。（來源：smm-cmm-library）
- 中型工具專案的有效拆法：**共用「檔案格式契約」讓內容線與程式線並行**（PM 先定死 frontmatter/資料夾格式），最後派獨立驗收員真啟動實測、對兩線相容性——比串行快、且驗收會抓到 parser vs 內容對不上的問題。（來源：smm-cmm-library）
- **並行雷：測試檔撞名刪到真交付物**。程式線為驗證臨時造了一張跟內容線同名的測試卡（`BO-報表.md`），清理時把內容線真正建的那張一起刪了。工單要規定：agent 造臨時測試檔一律用不會撞產出命名空間的名字（如 `__tmp__` 前綴／獨立測試資料夾），清理只刪自己造的。PM 收尾要核對交付物數量對不對。（來源：smm-cmm-library）
- **內容型專案的順暢流水線＝「writer 出多候選＋推薦組合 → PM 二級升級 → writer 細規格 → dev → qa → PM 收尾 commit」**：規劃階段讓 writer 提 3~4 候選並自己推薦，PM 只把「輕碰核心原則／改變產品哲學」的取捨升級給 Benson 拍板，其餘 dev 層 UX/調參 PM 自己拍板即可（別什麼都問老闆）。qa 通過後若有非阻擋小建議，趁 dev 還熱一次收掉再 commit，成本低、可維護性高。（來源：office-cat v0.8）
- **收工鐵律的具體落點**（team-lab）：專案專屬「設計決策備忘」寫進該專案 CLAUDE.md（含「後續別誤改」的界線，例如某數值邊界是老闆批准的、某結構刻意跟另一個分開）；跨專案 PM 流程教訓才寫這裡 D 段。（來源：office-cat v0.8）
- **「本機 App 為真本＋GitHub 公開 repo 為跨裝置同步中樞」模式**（來源：recipe-book）：想讓一個本機工具「手機也能用、到哪都看得到」又不想付雲端/API 費——本機 Node App 當真本＋AI，資料 push 到 GitHub 公開 repo，GitHub Pages 服務一份 PWA 給手機。前端做 DataStore 抽象、依 `location.hostname` 切「本機全功能」/「Pages 版」。本機存檔後自動 `git pull`(衝突用固定策略如 `-X ours`)＋`push`、啟動時也 pull；另一端（手機）用 **GitHub Contents API** 直接讀寫，金鑰用 **fine-grained PAT 只授權那一個 repo 的 Contents**、存 localStorage（本人產本人貼、AI 不經手）。
- **PWA 上 GitHub Pages 專案站在子路徑 `/repo/` 下**（來源：recipe-book）：所有資源、`manifest` 的 `start_url`/`scope`、service worker 的 scope 一律用**相對路徑**，別用開頭 `/`，否則子路徑下全 404。Pages「Deploy from a branch」只能選 root 或 `/docs`；用 build 從單一來源 `public/` 鏡射到 `docs/`、別維護兩份會分岔的前端。
- **iOS Safari 表單自動放大**（來源：recipe-book）：點進 `font-size < 16px` 的 input/textarea/select 會自動 zoom、放大後點不到底部按鈕。根治＝所有表單欄位 **font-size ≥ 16px**（別用 `maximum-scale=1` 那種傷無障礙的做法）。
- **已安裝的 PWA 要吃到新版**（來源：recipe-book）：SW 要 `skipWaiting()`＋`activate` 時清舊快取＋`clients.claim()`，資料類請求 network-first（別 cache-first 服務到舊資料）。**換 icon 後 iOS 需把 App 從主畫面移除、重新加一次**才會換。
- **GitHub 匿名 vs 認證讀取的即時性**（來源：recipe-book）：未帶 token 的 GitHub `contents` API 會**嚴重快取/延遲**（可能回好幾版舊資料）；要即時就**帶 token 走認證 API**。raw CDN 也會快取 → 用 `?t=<blob sha>` cache-buster。寫入後用**樂觀更新**（直接拿剛送出的資料更新畫面）避免「存了卻看起來沒存」的錯覺。
- **tool-manager＝Benson 的工具啟動面板**（`Desktop\Claude Work\tool-manager`，localhost:4900）：team-lab 做出可常駐/可啟動的工具後，順手加進 `tools.json`（一筆物件：id/name/emoji/category/cwd/command/port/url/processMatch）讓 Benson 一鍵啟動、不用自己點 start.bat。分類用 `category` 欄位（目前分組：**作品**／**AI 工具**）。server.js 熱讀 tools.json，但**改 server.js 或加新欄位要重啟面板**才生效；`PORT` 可用 `TOOLMGR_PORT` 覆寫方便另開臨時實例測試。
- **美術需求別硬用程式手刻**：Benson 嫌醜的東西，agent 手刻 SVG/像素三輪迭代也追不上「真的畫出來」的品質——及早改道「**Benson 用 ChatGPT 生圖（每次附角色參考圖保角色一致）＋ agent 負責去背/裁切/接入程式**」。**動畫不叫 AI 生逐格幀**（生不出「同一隻只差一點」，必歪）——一個姿勢一張靜態圖，動作用程式「切區塊做整數像素位移」（呼吸/打字/眨眼都做得出）；像素圖**永不縮放變形**（會糊）。（來源：office-cat v0.9）
- **視覺產出要「機器驗收」不能只肉眼**：動畫幀用「與底圖做像素差異 → 實際動的 bbox 必須落在設計區域內」自動稽核，一抓就抓到「打字動到鍵盤」的座標位移雷（根因：正式管線與試作的裁切方式不同、座標系整個位移——**試作代碼轉正式時，座標常數必須跟著管線重新標定**）。稽核腳本留在專案 tools/ 每次重烘必跑。（來源：office-cat v0.9）
- **⭐ 先確認素材的本質，再決定管線**（來源：office-cat v1.2→v1.3，最貴的一次繞路）：把 Benson 用 AI 生的圖當成「真像素圖」壓到原生格（50×50）再整數放大 ⇒ 他回報「邊框變粗糙」。真相是那是**像素風插畫**（邊緣本來就有細膩層次），正解是**直接烘到顯示尺寸、只縮不放**。押錯本質，整條管線白做一輪。同期教訓：降採樣要**取眾數不取平均**（平均會生出原圖沒有的過渡色）→ 但那是給真像素圖的；插畫路線改用高品質縮圖不量化。
- **位移式動畫在放大尺度會撕裂**（來源：office-cat v1.4.1）：「整塊搬走、原地留舊內容」的 `shift` 手法，切線只要穿過眼睛/五官就會把它複製拉長。小尺度（位移 1px）看不出來，**尺度放大後全部現形**（19 幀中 14 幀）。會伸縮的部位一律改「**以一邊為支點的錨定伸縮**」（支點那列不動＝零接縫），`shift` 只准用在剛體小物件。並補「撕裂偵測」自動檢查、**且檢查本身要有自我校準**（拿舊做法現場測一次，確認偵測器沒被改壞）。
- **PWA 改版的正解是「告知」不是「自動 reload」**（來源：lose-weight-helper → travel-book v1.4）：殼是 cache-first，新 SW activate 後畫面仍跑舊 JS，**使用者完全看不到這件事，只會覺得「怎麼沒有新功能」**。標準做法：`APP_VER` 當唯一版本來源（跟 SW cache 版本號**一起 +1**）；偵測走 `registration.updatefound` → `installing.statechange === "installed"` **且已經有 controller**，加上 `controllerchange`，**兩條都要留**，並用進站時記下的 `hadController` 擋掉「第一次安裝」誤報。**偵測到不要自動 reload**——使用者可能正在輸入，改成跳提示由他自己按「立即更新」。另給一顆「檢查有沒有新版本」＝`reg.update()` 再等 ~1.2s 讓 handler 跑完。
- **同架構的 App 之間可以互相抄機制**（來源：travel-book ← lose-weight-helper）：Benson 手機版 Claude Code 做的 App 程式碼不在這台電腦，但 **repo 公開** → 直接讀 GitHub 原始碼把機制搬過來，不必重新設計。他說「某某 app 有個功能很棒」時，先問是哪一個功能、再去讀那份 repo，比自己重想快得多。
- **測試會寫入使用者真實資料的流程時，先把 persist 函式換成空函式**（來源：travel-book v1.6）：在瀏覽器 console 把 `persistTrip` 暫時換掉，就能**跑完整條表單送出路徑**（驗到 handler、render、toast）而一個位元組都不落地，測完 reload 丟掉記憶體變更。比造假資料更真、比直接寫下去安全。順帶：測到一半發現他的資料變了，要先查證是不是自己寫的（看 git log 的 commit 時間與 diff），別急著回報。
- **需求聽起來比一句話大的時候，先用他的真實資料演一次給他看**（來源：travel-book v1.6）：Benson 描述「改一個後面全部要手動改」時先問「你懂不懂我的意思」——回他一段用**他自己 Day 1 的行程**推演的前後對照，確認理解一致才動手。同理，純視覺的取捨（要長什麼樣）就做幾個版本的 mockup 讓他挑，別用文字描述。這兩步都省掉整輪白工。
- **⭐ 純靜態網站也做得出「登入」體驗**（來源：keyring）：Pages 沒有伺服器可以驗密碼，但可以把要保護的東西（GitHub PAT）**用每個人的密碼加密後放公開 repo**，前端用 WebCrypto（PBKDF2-SHA256 600k → AES-GCM 256）解開；**密碼錯＝GCM 驗證失敗，不必另存 hash**。體感就是登入，零伺服器、零費用。代價要對使用者誠實講：密文是公開的、沒有「忘記密碼」（只能由管理者重設）、加密碼不等於資料變私密。**裝置存「派生金鑰」而不是密碼**——這樣後台換 PAT 時各裝置自動換過去、換密碼則舊裝置自動失效。
- **⭐ 讓 agent 全程用假機密開發與驗收**（來源：keyring）：要驗的是「加密進去的字串，解鎖後拿不拿得回同一個」——**round-trip 相等性用假 token 驗得一模一樣完整**，真機密由 Benson 自己在本機後台貼一次。工單直接寫死「不要向任何人索取真金鑰」。這條適用於所有碰到金鑰／密碼／憑證的專案。
- **PM 該把哪些「建議級」升級成必修**（來源：keyring 退件那輪）：兩個判準——①**現在改幾乎零成本、之後改要做資料遷移**（例：使用者 id 用中文 vs ASCII slug，而且這台的專案吃過一模一樣的虧）；②**它砸在第一印象上**（例：解鎖名單被快取整個 session ⇒「我幫你設好密碼了」→ 對方點開卻看不到自己）。反過來，純美觀瑕疵留給 dev 順手收。
- **第一次使用一定會失敗的路徑，要當成主流程做**（來源：keyring）：需要外部前置條件（開 repo、給權限、裝東西）的工具，**新手第一個畫面就是錯誤畫面**。做法：①開機就自我體檢，不要等他存第一筆才報錯；②錯誤分類，每類給人話＋編號的下一步；③一定要說「東西已經存在本機了、不會不見」；④能自動化的那段給一顆按鈕（例「🔗 幫我接起來」＝本機 `git init`＋`remote add`），**但不可逆的動作（開 repo）留給他自己按**。
- **agent 說「那條沒過是我測試斷言寫錯」時不要直接採信**（來源：keyring 複驗）：那是自我開脫最常見的形狀。做法是交代 QA **獨立重驗那一條**。同理 QA 也會自己抓到「上一輪某條其實沒真的測到（測試工具的旗標沒生效）」——**旗標沒生效＝那條等於沒測**，要重跑。
- **⭐ 「醜」有時候不是品味問題，是壞的**（來源：keyring v2.0→v2.1）：Benson 說解鎖畫面「有夠醜」，查下去發現主要 CTA（珊瑚色「解鎖」鈕）**實際上是透明的**——模組自帶的 `.kr-sheet button{background:none}` reset 權重壓過了 `.kr-go`。**純功能測試永遠抓不到這種 bug**（按鈕點得動、流程全過），要**把每個可互動元素的 computed style 實際量一遍**（背景色、文字色、尺寸、圓角）才看得見。老闆抱怨外觀時，先驗有沒有壞，再談設計。
- **⭐ 把樣式模組注入「本身就有 CSS 的宿主 App」時，權重一定會被吃**（來源：keyring）：`.kr-chip`(0,1,0) 輸給宿主的 `.home-foot button`(0,1,1)。**修法不可以寫成 `.home-foot .kr-chip`**——那把宿主 DOM 結構寫死進模組，複製到下一個 App 就再壞一次。正解是**自我加倍**（`.kr-chip.kr-chip`，0,2,0），不依賴宿主結構；而且要**整份規則一起掃**，不是補發現的那兩條。順帶把 font-family／appearance／margin／line-height 也鎖死，避免宿主滲入。
- **樣式注入時機要在 `init()` 不是第一次 `paint()`**（來源：keyring）：只在開啟某個 UI 時才注入樣式，會讓「還沒開過那個 UI」的常駐元素（例如 footer 的身分藥丸）**完全沒有樣式**——而那往往是使用者每次進站就看到的入口。
- **自己測出來的異常，先懷疑自己的測法**（來源：keyring 最終簽收）：PM 反覆 `unregister()` 後立刻 `location.reload()`、又在**背景分頁**（被瀏覽器節流）觀察，得到「SW 註冊數 0 ＋ fetching the script 錯誤」，看起來像 PWA 壞了。實際上是註冊還在進行就被 reload 打斷。**判斷不了的時候要說「我判斷不了」並交給獨立驗證**，不要自己下結論也不要沉默放行；背景分頁量到的版面尺寸（寬度回報 0）同樣不可信。
- **老闆說「我不想幫你判斷」時**（來源：office-cat 美術線）：那是要 PM 自己拿專業判斷＋自己驗收，不是繼續丟選項給他挑。做法：拉獨立角色（lab-ux）做**有數據的診斷**（它甚至證偽了 PM 的假設、找到真根因），PM 自己目視驗過、判定合格才交付。交付時講「我判定合格」而不是「你看看醜不醜」。
- **子代理斷線（API error）後**：工作區會留半套修改。用 SendMessage 讓原代理接續（transcript 還在），把 IDE 診斷的未完成清單餵給它；但**診斷可能是過期快照**，接續者要先重驗磁碟現況再動手。（來源：office-cat v0.9）
- **Claude 內建瀏覽器面板的合成按鍵 ≠ 真實鍵盤**：用 computer key "Return" 測「Enter 送出」會測不到（頁面 keydown 收不到），但真實使用者沒問題——別因此誤判成 demo bug 退件。正確驗法：javascript_tool 對 input `dispatchEvent(new KeyboardEvent('keydown',{key:'Enter',...}))` 驗 handler 有接；另外表單做成原生 `<form>` + `type=submit` 是最穩的 Enter 送出路徑（IME 組字 Enter 原生不誤送）。（來源：roundtable-board）
- **「接本機 claude 當大腦」的三個新雷**（來源：roundtable-board）：① **cwd 要指到中性 temp 資料夾**——以專案為 cwd 時 claude 會自動吸專案 CLAUDE.md，角色開口就洩漏開發脈絡；② 角色人格用 `--append-system-prompt`，人格裡明寫「本場無工具、嚴禁捏造數據」，模型就會主動聲明沒接工具而不是編數字；③ **多 agent 對話引擎的已讀游標（seenUntil）只能在「餵進 prompt 前」推進**，回覆落地後不可覆寫成最新——否則生成期間（20~40 秒）插進來的訊息會被標已讀但從未餵過、被無聲忽略；角色自己的發言靠 `--resume` session 記憶、組增量時濾掉即可。
- **⚠️ 安全鐵律：`--add-dir` 不是讀取邊界**（來源：roundtable-board v1.2）：headless `claude -p` 給 `--allowedTools "Read"`（不帶路徑）＝**整台機器任何檔案都讀得到**，add-dir 只是「額外工作目錄」不是白名單。要做唯讀沙箱必須用**路徑限定 allow 規則**：每個授權目錄 × 每個工具各一條 `Read(//C:/絕對路徑/**)` 型規則（路徑含空格時每條規則獨立 argv）。授權前先盤點目錄裡的金鑰（.env、credentials/、*.session、DB 備份），敏感物同夾的資料整夾排除。驗證要做「金絲雀測試」：拿清單外路徑實測真的被權限層擋（不是模型自律拒絕——驗權限層要用稽核框架問法：明說預期被擋、只准回報擋/沒擋、禁止輸出內容）。**且模型自報「成功/被擋」會幻覺**（QA 實抓兩次：Sage 自稱 Bash 執行成功、Claude 自稱讀到 .env 還把「已確認可讀含憑證」寫進給老闆的結論卡——實際權限層都擋住了、`permission_denials` 有記錄、無真外洩）——安全驗證一律要磁碟探針＋server log／permission_denials 佐證，不信模型嘴上說的。
- **接不同家 AI（如 OpenAI Codex CLI）的沙箱雷**（來源：roundtable-board v2.0）：Codex `codex exec -s read-only` 的沙箱**擋不住 cwd 以外的檔案讀取**（金絲雀實證：cwd=testkit 時讀到隔壁專案的 .env 真檔）——它的 read-only 是「不能寫」不是「不能讀出範圍」。跨家模型要餵檔案討論時，若一家無法可靠限制讀取範圍，用**非對稱設計**：只讓能 scope 的那家（Claude，用 --add-dir 到乾淨子樹）有檔案權，另一家看引文。**且送 OpenAI 的內容＝離開本機**，敏感目錄一律 opt-out。Codex 整合的 Windows spawn／旗標順序雷記在該專案 CLAUDE.md。
- **AI 產出直接給老闆看時要有免責層**（來源：roundtable-board v2.0）：討論/結論類工具的最終產出（結論卡、報告）會夾帶 AI 幻覺斷言（實錄：憑空寫出假的安全結論），UI 要固定一條「AI 生成、事實/數據/安全/金額需人工複核」免責提示——這是產品層防線，不能靠 AI 自己不出錯。
- **UX demo 階段用 Claude「私人 Artifact 網頁」直接給 Benson 手機試玩**（來源：travel-planner）：單檔零依賴的 demo HTML 可去掉 doctype/html/head/body 骨架後發成 Artifact（預設私人、claude.ai 網址），Benson 用 iPhone 點連結就能玩——不用先開 GitHub repo/Pages、不用傳檔。正式版才走三層架構。發佈前 PM 必須完整讀過檔案內容。
- **跨裝置同步工具的 id/檔名正規化必須「單一規則、全端同字元集」**（來源：travel-book v1.0 QA 退件）：server 端 sanitize 與前端 slugify 字元集不一致（一邊只留漢字、一邊留全部 `\p{L}`），會讓含假名/韓文的資料在跨裝置編輯時被改名成新檔 → **無聲分裂成兩筆並隨同步擴散**。規則要抽成同一套（`\p{L}\p{N}._\-`＋basename 防 traversal），且 QA 測 round-trip 必須用非漢字 CJC 字元（假名/韓文）當測資，光測中文抓不到。
- **老闆在既有框架下「自己想辦法變通」＝需求訊號**（來源：travel-book v1.3）：Benson 自建一個「🚗 移動」類別、把車程當行程點記——那是缺功能時的湊合，不是滿足。看到這種變通要主動辨識背後真需求（他要的是時間軸上「站點 vs 路上」兩種層級，不是多一個類別）。回應時先把理解講清楚再動手，他會確認「你懂我真正的需求嗎」。
- **交付前 PM 要補子代理測不到的面向**（來源：travel-book v1.3）：dev 明說「這個 session 沒瀏覽器工具、視覺沒驗」時，PM 自己起 server＋瀏覽器補驗再送 QA（截圖不可用時，改用 `getComputedStyle`／`getBoundingClientRect` 量測做**數值化視覺驗收**：高度對比、底色、陰影、字級、rail 樣式——照樣抓得出層級對不對）。臨時測試資料一律另建 `__tmp__` 旅程、驗完刪除，絕不寫入老闆真資料。
- **拖曳排序在「混合高度清單」的雷**（來源：travel-book v1.3）：讓位動畫過衝的根因常在**落點判定**而非位移量——用「各項原始中心點」判定時，矮項旁的高項要拖過頭才交換。正解是改用「被拖項頂端 vs 各插入格的目標頂端取最近」，位移量也用各項實際佔用高度累加。
- **⭐「功能好像只做一半」時，先做完整性體檢再動手**（來源：office-cat v1.5）：老闆的直覺常是對的但歸因不一定對。實測發現根因不是「沒寫完」，而是**寫完的東西掛在一輩子碰不到的門檻上**（心境四態一年全是同一態、領悟一年 0 條、心情 8 種只跑得出 3 種）。**單元測試驗「給定輸入→輸出對」，驗不到「這輸入在真實運行中會不會出現」**——行為型系統要有**長期模擬 + 分布門檻**（做成常駐指令，別跑完就刪）。
- **一個數值不可以兼兩份工作**（來源：office-cat v1.7）：`salience` 同時管「有多重要」與「最近講過沒」，實測後者每天扣的分碾壓前者能加的分 ⇒ **數學上只能活一個**。遇到「調參怎麼調都不對」時，先問這個數值是不是被賦予了互相矛盾的職責。
- **AI 輸出品質：guard 只擋得住它認得的詞**（來源：office-cat v1.9）：36 筆真實輸出禁詞命中 0%，人工卻找到 8 類問題（格言化／記帳／虛構／空泛）。**再加正則沒用，要固定情境集 + 人工複查**，並做成常駐指令（`npm run voice-audit`，跑前印預估成本、沒 key 安靜退出、key 只讀不落檔）。另：**新規則與舊材料打架時優先改材料**——材料寫「對方隔了幾天」卻叫模型別提，加禁令無效，把資訊拿掉才有效。
- **⭐ 驗收要驗「測試本身是不是承重的」——用突變測試**（來源：office-cat v2.1 整地）：dev 交來「我補了測試證明 X 會發生」，QA 不是讀測試碼判斷，而是**故意把程式弄壞、看那支測試會不會紅**（備份→破壞→跑→還原，並用 SHA-256 驗證還原無誤）。這一招當場證偽了 dev 的因果敘述（牠說 R-2 儀式掛在 A 欄位，突變後 A 歸零 R-2 照樣發生 ⇒ 真正的開關是 B）。**「有測試」不等於「測試在保護那件事」**；宣稱「唯一觸發條件是 X」之前一律先做突變測試。同理，QA 驗「數值沒被動到」不要採信報告，要拿**動手前留下的原始輸出逐行 diff**。
- **⭐ 門檻要分兩種，而且「零餘裕的綠燈」是警訊**（來源：office-cat v2.1 整地）：長期模擬的檢查線混了兩類——**硬界線**（產品承諾／數學 clamp／存活檢查，餘裕 0 是本質）與**校準帶**（該有餘裕、翻紅代表要重新校準）。混在一起時，一條隨機翻紅的線會讓人分不出「該校準」還是「真壞了」。做法：①**換 4 組隨機種子跑同一份程式**量出這條線自己的雜訊帶，落在帶內就是會發假警報的線；②把定界方法做成**可重跑的入口**（`--seed-offset` 參數，並明訂「只有 offset=0 是驗收基準」「一組種子的實測值不叫 band」），否則下次沒人能重驗——這是「探針跑完就刪」的同一個病。
- **訂門檻前先問「這個統計量在母體變動時穩不穩」**（來源：office-cat v2.1，同一類錯犯了三次才收斂）：**比例型**（佔比、覆蓋率）對母體大小不敏感，優先用；**次序統計量**（min/max/p5）只在母體本身是硬界線時可用；**絕對計數**只在母體規模被凍結時可用，規模會長就換比例；**存活檢查**的母體要先剔掉結構性稀有成員，否則不算硬界線。另一半是**指標要與命題對齊**——「最不重要那條記憶有多不重要」證不了「牠會忘掉小事」，改成「已明顯淡忘的佔比」才對得上。**指標選錯時，調門檻怎麼調都不對。**
- **PM 對「dev 自己抓到、但不在退件清單」的發現要當場裁示**（來源：office-cat v2.1）：dev 修完退件後用新工具又抓到同病的第七條，刻意不動、來問——因為牠剛被退件的理由正是「只憑一組數據就動門檻」。這種自律要**明確肯定並當場給裁示**（該修就趁 dev 還熱一次收掉）。反之，**子代理回報「發現但沒處理」的清單一定要求牠寫進 repo**，留在對話裡等於沒留。
- **IDE 診斷（new-diagnostics）常是子代理施工中的過期快照**（來源：office-cat v2.1，連續三次）：看到一片紅先自己跑一次 `tsc`／測試驗磁碟現況，不要據此退件或叫人重做。
- **⭐「這批很安全」要有機器證明，不能靠人分類**（來源：office-cat v2.2a）：把工作分成「安全批（不影響 X）」與「需重新校準批」時，**安全的定義要做成一條會紅的紅線**，然後讓安全批跑一次——dev 自己分類為安全的 12 項裡，有 1 項實測整片翻紅（改的東西看似無害，但改變了流程分支 ⇒ 亂數呼叫次數變 ⇒ 整條序列位移）。**分類是判斷，紅線是證據**；沒有紅線的「安全批」只是宣稱。抓到之後正確處置是**把那一項移到校準批**，不是放寬紅線。
- **「機率很低」與「分母是 0」要分清楚**（來源：office-cat v2.2a）：一批功能一年只觸發 0~1 次，直覺是「調高權重就好」——實測發現它的前提條件在正常運作下**佔比 0.000%**，那 0~1 次全來自另一條破口。**分母是 0 時，調權重是白做**。診斷罕見現象時，先分別量「前提成立的比例」與「前提成立時的命中率」，別把兩者混成一個「機率」。
- **定界掃描不要跳號**（來源：office-cat v2.2a，QA 補抓）：用多組種子掃描定出「X 是守得住的最小值」時，掃描表若跳過相鄰點（掃了 6 和 8 沒掃 7），那個「最小」就沒有證據。QA 補掃相鄰點才算完成；把相鄰點的實測寫進註解，下一個人才不必重跑。
- **⭐ 重設基準線必須有「對照組」**（來源：office-cat v2.2b）：當一次改動**刻意**讓回歸紅線失效（例如重新校準、換演算法），要重產基準才能繼續——但重產這個動作本身會讓紅線自動變綠，防線瞬間變成橡皮圖章。守法：①**授權要留紀錄**（誰批准、為什麼、斷點是哪個 commit、舊基準保留不刪）；②宣稱「只有該變的變了」之前，**先留一組完全沒被碰到的項目當對照組**——實測發現對照組自己也有 ±25~30% 的個別擺幅，但**合計只有 +0.6% 且上下各半** ⇒ 證明「單項不可讀、只有分組合計可讀」。**沒有對照組就不要宣稱只有預期的變了**，那只是眼力。紅線的語意可以從「證明什麼都沒變」升級成「證明只有該變的變了」，但它仍然是硬界線。
- **豁免名單要有「防塞入」斷言**（來源：office-cat v2.2b）：把「結構性稀有」的項目從檢查母體剔除是合法的（否則那條線就是擲骰子），但剔除不等於放生——①存活改用**不靠抽樣的單元測試**證明（給定必中的隨機、排除其他候選，斷言它真的被選出來），並配一個**反向對照**證明該測試不是恆真；②**斷言豁免名單的長度**，擋的是未來有人把礙事的項目偷偷加進去矇混過關。QA 用突變測試證實這條會擋。
- **⭐「這東西變得很難測試」＝產品盲點的徵兆，不只是工具問題**（來源：office-cat v2.3）：Benson 說「app 變得有點難測試了，順便看看好不好玩」——這兩件事是同一件。那是一隻照真實時間過日子的貓，**要看牠一年得等一年 ⇒ 他沒辦法快速體驗，自然也沒辦法判斷好不好玩**。正確反應不是道歉或加測試，是**先做出「讓人能親眼看見整段體驗」的東西**（把一年份生活印成人讀得下去的紀錄），再談品質。副作用是：團隊自己也是第一次看見完整體驗，當場抓到一堆統計看不出來的問題。
- **覆蓋率綠燈 ≠ 好玩，而且會把人騙住**（來源：office-cat v2.3）：連做三版把「內容跑不跑得到」修成全綠之後，實際讀完整體驗才發現真正的災區是**每天必看的固定插槽**（最常見的那格只有 3 句、一年重複 63 次）——我們**補句補在「會讓體檢變紅的那一格」，不是「會被看到的那一格」**。**驗收指標會決定你修哪裡**，所以要定期用「使用者真的會遇到什麼」重新校準指標，而不是一路優化指標本身。
- **用平均當可接受性判準＝用中位數保證尾巴**（來源：office-cat，同一錯誤犯兩次）：「平均每句一年出現 8.6 次，可接受」→ 實際分布極偏，頭部是平均的 4~6 倍（最壞的一條一年 49 次而它只有 1 句）。凡是「平均值可接受」的結論，一律再問一次**最壞的那個是多少**。
- **守衛要寫成白名單，不是黑名單**（來源：office-cat v2.3，QA 實證）：工具唯一會覆寫使用者真資料的地方，守衛原本是「路徑落在真存檔目錄就中止」——QA 拿一個**打錯的相對路徑**測，它解析到別處、不在黑名單內於是放行，真的在桌面樹下寫出一份檔案。訊息寫的是「一律只寫到隔離路徑」＝白名單語意，實作卻是黑名單。**改成「解析後必須落在指定沙箱底下，否則中止」**，災難路徑因此被封死兩次。通則：**擋破壞性操作時列舉「准許的地方」，不要列舉「禁止的地方」。**
- **⭐「同時段比較」還要再防一層：資料落後**（來源：telegram-issue-tracker DB SQL 每日改善追蹤）：做「今天 vs 昨天」時大家都記得「今天是半天，要比同時段」，但**批次收資料的系統還有第二個坑——今天的分子停在最後一次 collect，昨天的分母卻是完整的**。實證：同一份 DB 不動，10:5x 看是「▲+8% 變差」、13:0x 變「▼-29% 變好」、23:00 會變「▼-66%」，純粹因為比較窗跟著牆上時鐘往後開。**正解：cutoff = min(現在的小時, 今天已收到的最後一筆資料的小時)**，並在畫面標「資料只到 HH:MM」，落後超過門檻就**拒絕下結論**而不是照算。通則：**任何「趨勢/改善」指標，分子與分母的資料完整度必須一致，且要把不一致顯性化。**
- **⭐ 突變測試要專打「沒有測試守著的那一側」**（來源：同上，QA 兩輪實證）：dev 自己做突變 13 處全紅，看起來很安全——但那 13 處**全在有測試的那一側**。QA 反向挑「可能沒防線」的地方打，8 處有 **5 處把程式弄壞了測試照樣全綠**（DOM 層文案門檻、失敗態收合、規格某條配對條件），而**該輪的兩條退件正好就掉在那 5 處裡**。通則：突變測試的價值不在「證明我的測試會紅」，而在**找出哪裡打不紅**；打不紅的區塊就是下一個 bug 的落點。延伸：驗收數值型紅線（如對比度）時要打「非直接目標」（改底色而不是改前景色），才知道那條線量的是合成後的真實值還是死背的常數。
- **先過濾再取極值 ＝ 隱藏的口徑分岔**（來源：同上）：同一頁兩個區塊算出不同的比較窗，根因是舊函式**先做 side 過濾、再從過濾後的資料求「最後一小時」**。預設值（BO）剛好等於全域最大值，所以**只測預設值永遠看不到**，換一個篩選條件才現形。通則：**極值/邊界一律在過濾前算**；測試要對每個篩選值做迴圈斷言，不能只測 default。
